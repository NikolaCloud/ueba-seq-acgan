# Глубокий анализ первого эксперимента

## Установленные причины низкого качества

1. **Недостаточная разметка r3.1.** В answer key только 345 аномальных событий:
   35 в r3.1-1 и 310 в r3.1-2. При строгой хронологии train видит семь
   аномальных окон только первого сценария; validation/test — второй сценарий.
   Это проверка переноса на неизвестный тип атаки, а не достаточная выборка для
   supervised conditional GAN.
2. **Сильная асимметрия признаков.** Например, normal p99 для числа
   after-hours событий равен 16 при максимуме 393, а для HTTP — 390 при
   максимуме 687. Обычный RobustScaler оставляет длинные хвосты, из-за которых
   генератор выдаёт значения вне реалистичного диапазона.
3. **Дисбаланс состязательной игры.** Source-head выдавал real ≈0.94 и fake
   ≈0.054. Значит, дискриминатор легко побеждает генератор; улучшать detector
   на таких synthetic samples нельзя.

## Принятые меры

- Основным датасетом становится CERT r4.2: answer key содержит 70 акторов и
  7 323 размеченных события трёх сценариев, что радикально увеличивает число
  условных примеров.
- Препроцессор обобщён на answer key разных выпусков, включая вложенные файлы
  r4.2.
- Добавлен `BoundedLogTransformer`: `log1p` для счётчиков, clipping по train
  99.5-перцентилю и отображение в `[-1, 1]`. Это исключает выбросы из
  генеративной игры и позволит ограничить выход генератора `tanh`.

## Критерий улучшения

Следующая версия принимается только если на validation одновременно:

1. средняя source-вероятность реальных и synthetic рядов сближается;
2. сокращается разрыв средних и стандартных отклонений признаков;
3. TSTR не хуже baseline без синтетики;
4. метрики test сообщаются только после фиксации модели по validation.

## Аудит r4.2 answer key

Проведён до окончания распаковки raw-логов. В r4.2 есть 70 акторов,
70 сценарных окон и 7 323 размеченных события: 3 860 HTTP, 2 785 device,
470 email, 198 logon и 10 file. События покрывают три типа сценариев.

Для воспроизводимой хронологической оценки выбраны границы: train до
30.11.2010 включительно, validation — декабрь 2010–январь 2011, test — с
01.02.2011. По answer key это даёт:

| Разбиение | События | Пользователи |
| --- | ---: | ---: |
| train | 4 889 | 54 |
| validation | 1 036 | 16 |
| test | 1 398 | 15 |

Такое разбиение не смешивает будущее с прошлым и сохраняет положительные
примеры во всех трёх частях.
