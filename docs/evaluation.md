# Оценка Seq-ACGAN

```powershell
$env:PYTHONPATH = 'src'
python scripts/evaluate_seq_acgan.py
```

Проверяются четыре аспекта:

1. `anomaly_head` на реальных validation/test: PR-AUC, ROC-AUC, recall@50/100/500.
2. `source_head`: средняя вероятность «real» для реальных и синтетических рядов.
3. Условное сходство распределений: средний абсолютный разрыв средних и
   стандартных отклонений признаков в стандартизированном пространстве.
4. TSTR (train on synthetic, test on real): отдельный классификатор учится
   только на созданных последовательностях и тестируется на реальных.

Семь аномалий в train недостаточны, чтобы считать этот прогон доказательством
готового детектора. Метрики нужны для сравнения следующих версий модели и
конфигураций augmentation.

## Первый полный прогон

| Проверка | Validation | Test |
| --- | ---: | ---: |
| anomaly-head PR-AUC | 0.000513 | 0.000071 |
| anomaly-head ROC-AUC | 0.2885 | 0.3871 |
| anomaly-head recall@100 | 0.00 | 0.00 |
| TSTR PR-AUC | — | 0.000049 |
| TSTR ROC-AUC | — | 0.0413 |

Source-head присваивает настоящим последовательностям среднюю вероятность
`0.94`, а синтетическим — `0.054`: генератор пока заметно отличим. Средний
разрыв нормального класса в стандартизированном пространстве также высок
(`23.93` по средним и `77.24` по стандартным отклонениям).

**Вывод:** этот первый GAN-прогон является отрицательным контролем, а не
результатом для презентации. Причины: всего 7 аномальных train-последовательностей
и тяжёлые скошенные счётчики признаков. Перед повторным обучением нужно добавить
log-преобразование счётчиков, ограничение выбросов и более устойчивую GAN-loss
схему; для доказательства обобщения потребуется более крупный выпуск CERT.
